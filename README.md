# Bubble Grid Game

물풍선 격자 팀 대전 (1:1 · 2:2 · 3:3) 온라인 미니 게임 + 데디케이트 게임 서버.
외부 패키지 없이 **Node.js 18 이상**만 있으면 실행됩니다. (`npm install` 필요 없음)

## 실행

```bash
node server.js
# → http://localhost:8080  (같은 주소를 친구에게 알려주면 같이 접속)
```

브라우저에서 접속 → 닉네임/캐릭터 선택 → **온라인 게임** → 서버 1·2·3 중 선택 → 대전 방식 선택 → **게임 시작** → `매칭중..`

- 같은 서버에서 같은 대전 방식을 고른 사람끼리 인원이 차면 자동 매칭됩니다.
- 상대가 없을 때는 8초 뒤에 나타나는 **봇과 함께 시작** 으로 혼자서도 테스트할 수 있습니다.
- **연습 게임**은 서버 없이 브라우저에서 봇과 바로 대전합니다.

## 조작

| | PC | 모바일 |
|---|---|---|
| 이동 | 방향키 / WASD | 왼쪽 조이스틱 (물풍선 버튼과 동시에 사용 가능) |
| 물풍선 | Space / Enter | 오른쪽 물풍선 버튼 |

규칙: 물줄기에 닿으면 바로 탈락하지 않고 **물방울에 갇힙니다.** 팀원이 닿으면 구출, 상대가 닿으면 탈락, 4.5초가 지나도 탈락.
한 팀이 전멸하면 라운드 승리, 먼저 2승(기본)하면 매치 승리. 아이템: 풍선 개수 / 물줄기 길이 / 속도.

## 서버 구조 (서버 1·2·3 → 매칭 → 방으로 흩어짐)

```
접속자 ─► Channel(서버 1·2·3…)  ← 서버마다 정원이 있어 한쪽으로 몰려도 다른 서버는 영향 없음
              │  로비(채팅/접속자) + 매칭 대기열(1:1, 2:2, 3:3)
              ▼  인원이 차면
            Room(게임 방)       ← 매칭된 사람만 로비에서 빠져나와 이 방으로 "흩어짐"
                                   방마다 독립된 GameCore(서버 권위)를 60Hz로 실행하고 25Hz로 상태 전송
```

- 클라이언트는 **입력(방향/물풍선)만** 보내고, 서버가 계산한 상태를 받아 그립니다. (치트 방지, 모두 같은 화면)
- 매칭 도중/게임 도중 나가면 그 자리는 봇이 이어받아 남은 사람의 경기가 유지됩니다.
- 서버 보호 장치: 서버별 정원, 방 개수 제한, IP당 접속 제한, 메시지 속도/크기 제한, 느린 클라이언트 강제 종료, 오류가 난 방만 종료.

### 방장 방식 방 (로비 > 방 목록)

처음 방을 만든 사람이 **방장**이 되어 방장의 브라우저가 게임을 계산하고(봇 포함), 서버는 입력과 상태를 중계만 합니다.
방장이 나가거나 접속이 끊기거나 3초 넘게 멈추면 **다음 입장자가 방장을 이어받아** 방과 게임이 유지됩니다. 나간 사람 자리는 봇이 채웁니다.
한 판이 끝나면 모두 대기방으로 돌아갑니다.

- 주의: 방장 브라우저가 계산하므로 방장이 조작(치트)할 수 있습니다. 공정한 대전은 자동 매칭(전용 서버 방식)을 쓰세요.
- 방장 탭이 백그라운드로 가도 Worker 타이머로 계속 진행하지만, 모바일 브라우저가 앱을 재우면 멈출 수 있고 그 경우 자동 승계됩니다.
- 이 방식도 중계용 서버(`node server.js`)는 필요합니다. 서버 없이 브라우저끼리만 연결하는 방식(WebRTC)은 만들지 않았습니다.

### 서버 늘리기

```bash
# 1) 한 프로세스에서 채널 수 늘리기 (서버 1~5)
CHANNELS=5 node server.js

# 2) 컴퓨터/프로세스를 나눠서 실행 (서버 4~6을 다른 곳에서)
CHANNEL_START=4 CHANNELS=3 PORT=8081 node server.js
```

2번처럼 나눴다면 `public/config.js` 의 `servers` 에 각 주소를 적으면 서버 선택 화면에 모두 표시됩니다.

```js
window.BG_CONFIG = { servers: ['https://game-a.example.com', 'https://game-b.example.com'] };
```

### 환경변수 (모두 선택)

| 이름 | 기본값 | 설명 |
|---|---|---|
| `PORT` / `HOST` | 8080 / 0.0.0.0 | 포트 / 바인드 주소 |
| `CHANNELS` | 3 | 이 프로세스가 여는 서버(채널) 수 |
| `CHANNEL_START` | 1 | 첫 서버 번호 (여러 프로세스로 나눌 때) |
| `CHANNEL_CAP` | 100 | 서버 1개의 접속 정원 |
| `MAX_PER_IP` | 8 | IP당 동시 접속 수 |
| `ROOM_WINS` | 2 | 매치 승리에 필요한 라운드 수 |
| `HOST_STALL_MS` | 3000 | 방장이 이 시간 이상 상태를 안 보내면 방장 교체 |
| `BOT_FILL_AFTER_MS` | 8000 | 봇으로 채우기 버튼이 열리는 대기 시간 |
| `ALLOWED_ORIGINS` | (모두 허용) | 허용할 사이트 주소(쉼표 구분) |
| `TRUST_PROXY` | 0 | 1이면 리버스 프록시의 `X-Forwarded-For` 를 클라이언트 IP로 사용 |

## 인터넷에 올리기 (진짜 온라인)

게임 서버는 **계속 켜져 있는 Node.js 프로세스**가 필요합니다. GitHub Pages 같은 정적 호스팅만으로는 실시간 서버를 돌릴 수 없습니다.

1. **서버 + 화면을 한 곳에서**: Render, Railway, Fly.io, VPS 등 Node.js를 실행할 수 있는 곳에 이 폴더를 올리고 시작 명령을 `node server.js` 로 지정합니다. 호스팅이 지정해 주는 `PORT` 환경변수를 서버가 자동으로 사용합니다. 같은 주소로 접속하면 끝입니다. (HTTPS 주소면 WebSocket은 자동으로 `wss://` 를 씁니다.)
2. **화면은 GitHub Pages, 서버는 따로**: `public/` 폴더를 Pages에 올리고, `public/config.js` 의 `servers` 에 게임 서버의 **https 주소**를 적습니다.
   이때 게임 서버에는 `ALLOWED_ORIGINS=https://내아이디.github.io` 를 설정하면 다른 사이트가 서버를 쓰지 못하게 막을 수 있습니다.
3. 리버스 프록시(nginx, Cloudflare 등) 뒤에서 돌릴 때는 WebSocket 업그레이드를 허용하고 `TRUST_PROXY=1` 을 설정하세요.

무료 호스팅은 일정 시간 접속이 없으면 서버가 잠드는 경우가 있어, 처음 접속할 때 서버 목록이 늦게 뜰 수 있습니다.

## 파일 구성

```
server.js          게임 서버 (채널·매칭·방·봇 채우기·HTTP 정적 파일/상태 API)
wslite.js          의존성 없는 WebSocket 서버 구현 (RFC 6455)
public/
  index.html       화면 구조 (타이틀 · 서버 선택 · 로비 · 게임 · 매칭중)
  style.css        UI 스타일
  client.js        화면 전환 / 네트워크 / 렌더링 / 입력 / 효과음
  core.js          게임 규칙 (서버와 브라우저가 같이 사용)
  config.js        접속할 서버 주소 목록
test/
  core-test.js     게임 규칙 테스트        node test/core-test.js
  smoke-online.js  서버·매칭·방 통합 테스트  node test/smoke-online.js
  host-rooms.js    방장 방식·승계 테스트    node test/host-rooms.js
```
